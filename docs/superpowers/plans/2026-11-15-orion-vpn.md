# Operator VPN into orion (WireGuard) — as built 2026-11-15

**Why:** every internal service on the orion box (the k3s API, the world panel, Grafana, Garage admin,
Keycloak admin, login, …) was reached through an ssh tunnel plus one `kubectl port-forward` each. A
WireGuard interface on the box routes the operator's machines straight into k3s's networks instead:
every Service answers at its in-cluster name.

## Using it

- `just orion-vpn-status` — box ping, cluster DNS, k3s API, Grafana by name. `just orion-vpn-up|orion-vpn-down`.
- Services: `http://<service>.<namespace>.svc.cluster.local:<port>`, e.g.
  `http://kube-prometheus-stack-grafana.monitoring.svc.cluster.local/`, `http://panel.panel.svc.cluster.local/`,
  `http://garage.garage.svc.cluster.local:3903` (Garage admin API), `http://login.login.svc.cluster.local/…`.
- **Garage admin API** (the `garage-buckets` root, the CLI): `http://garage.garage.svc.cluster.local:3903` — the
  garage root's `admin_url` output (applied 2026-11-15). VPN down: `just orion-garage-admin` and
  `-var garage_admin_url=http://127.0.0.1:3903`.
- **Keycloak admin console and API** (the `keycloak-realm` root): `https://keycloak.vpn.errantry.renownandruin.com/admin/`.
  The console's browser code needs a secure context (https or 127.0.0.1), so plain http by the in-cluster name
  would not do: Keycloak serves TLS itself on 8443 (Service port 443) with a `letsencrypt-dns` certificate
  (module variable `admin_host`; the management port stays plain HTTP, `KC_HTTP_MANAGEMENT_SCHEME=http`, for the
  probes). The old `just orion-keycloak-admin` forward no longer opens the console while `admin_host` is set
  (Keycloak is told one admin address); VPN down for long → apply the keycloak root with `admin_host = null`.

### Applying the VPN-only names (first time; each apply asks before changing anything)

1. `just orion-init vpn-names && just orion-apply vpn-names` — IAM user + key, Secret, ClusterIssuer, CoreDNS
   ConfigMap (CoreDNS reloads it within ~30 s). Check: `kubectl --context orion get clusterissuer letsencrypt-dns`
   READY True; `getent hosts keycloak.vpn.errantry.renownandruin.com` → the keycloak Service's ClusterIP.
2. `just orion-apply keycloak -target='module.keycloak.helm_release.admin_certificate[0]'`, then
   `kubectl --context orion -n keycloak wait certificate/keycloak-admin-tls --for=condition=Ready --timeout=5m`
   — the certificate first, so the pod never waits on a missing Secret.
3. `just orion-apply keycloak` — the pod is recreated (strategy Recreate: about a minute without player logins).
4. `just orion-vpn-status` (keycloak admin 200) and `just orion-plan keycloak-realm` (no port-forward; no changes).

## Adding a device

`just orion-vpn-peer phone 3` → the box gets the peer (live and in `wg0.conf`), and
`target/orion-vpn/phone.conf` holds the device's config with its private key: move it to the device
(`qrencode -t ansiutf8 < …` for the WireGuard mobile app), then delete it. On a NetworkManager machine:
`nmcli connection import type wireguard file <name>.conf` + the split-DNS `nmcli connection modify` line from
the script's header. Removing one: on the box `wg set wg0 peer <pubkey> remove` and delete its `[Peer]` block.

## Not done (deliberately)

- The Hetzner Robot firewall: none is in the way today (the handshake works); if one is enabled later it must
  allow UDP 51820.
- `setup-host.sh` in survival-world does not install WireGuard — rebuilding the box means redoing the box rows
  above (`apt install wireguard-tools`, key, `wg0.conf`, `systemctl enable --now wg-quick@wg0`).
- More VPN-only names: add to the vpn-names module's `names`, then give the Service a TLS port with a
  `letsencrypt-dns` Certificate (as the keycloak module does). Anything plain-HTTP needs no name: use
  `<svc>.<ns>.svc.cluster.local`.
