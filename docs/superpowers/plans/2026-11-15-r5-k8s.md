# R5 — One World on k8s (orion and its k3d twin) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One world — a coordinator, two region hosts and its database — runs on orion's k3s under the Errantry hostnames; players enter through the live login service; a killed host pod is survived by a succession; the same manifests run on a local k3d cluster first.

**Architecture:** The server learns what a pod needs (names instead of IP addresses on its links, link identities from mounted files, an advertised peer address, a health and metrics endpoint, one client-facing certificate for QUIC and WebTransport, waiting for a forge instead of forging). A new `world` OpenTofu module (coordinator Deployment, host StatefulSet, per-host NodePort Services, a toolbox pod for `worldctl`, the web bundle) replaces the Agones-era one and is used by two roots: `deploy/envs/local/world` on k3d and `deploy/envs/orion/world`. The database is one CloudNativePG cluster with a database per world. Nothing reaches orion except through Dawid's hand steps (Phase D).

**Tech Stack:** Rust (quinn, rustls with ring, axum, prometheus), OpenTofu, k3s / k3d, CloudNativePG, cert-manager (HTTP-01), Traefik, ECR, nginx.

**Spec:** `docs/superpowers/specs/2026-09-20-multi-instance-k8s-postgres-research.md` §0 (R5 line: §0.10) and the handoff `docs/superpowers/plans/2026-11-15-r5-k8s-planning-handoff.md`. Absorbed plans, executed as written: `2026-11-14-errantry-player-facing-name.md`, `2026-11-14-hosts-to-errantry-renownandruin.md`.

## Decisions (Dawid, 2026-11-15, and what follows from them)

1. **R4 hand checks are a gate, not a precondition of the build.** `kill -9` and `kill -STOP` under `just dev-r3 2` have not been run. R5 is built now; Phase D Step 1 runs them before anything is applied to orion. The high correction counts per crossing stay an open observation and do not block.
2. **In R5:** the k3d local twin. **R5b, its own plan after this one:** the management panel. **Later:** several entry hosts (the elastic plan moves the login link to the coordinator), GDPR delete/export, rate limiting, autoscaling.
3. **First world:** id `errantry`, 2 hosts, `VOXEL_REGION_BLOCKS=256`, `VOXEL_CHUNK_BLOCKS=16`, `VOXEL_OWNERSHIP=claim` on the coordinator and on every host.
4. **An update is a stop and a start:** hosts scale to 0 (each leaves with a cut), every image is replaced, hosts scale back. Players rejoin by themselves (`REJOIN_MAX_MS` 60 s) or log in again. No two builds ever run side by side.
5. **Database:** CloudNativePG, one cluster `pg` (one instance) in namespace `postgres`, one database and one role per world, no pooler. Login's and Keycloak's databases stay their own StatefulSets (the elastic handoff defers consolidation). `pg` is the **world-side** instance of the future two-instance layout (management cluster vs region clusters, elastic design §10): no account, identity or chat data ever goes into it, and login reaches a world only through addresses that are module variables (`auth.login_url`, `web.login_upstream`, the login registry's `--link`) so they can become public names.
6. **Backups:** a nightly `pg_dump` of each world database to a Garage bucket, 7 kept. It survives a deleted volume, a bad migration and a bad rollback. **It does not survive the disk dying** — Garage is on the same disk. If the disk dies the world is re-forged.
7. **Hostnames:** the move to `errantry.renownandruin.com` is part of R5 (Phase C). **The game is served from `game.errantry.renownandruin.com`** (Dawid, 2026-11-15): the page, the QUIC and WebTransport endpoints of every host, and `/login`. That name is the k8s world's alone. The docker-compose game at `orion.factoriosurvivalworld.com` is never moved to the new name: R5 does not edit its files, and it is switched off when the k8s world is live (Phase D, last step).

## What the handoff got wrong (verified 2026-11-15)

- CloudNativePG is **not** installed on orion: `deploy/envs/orion/platform` uses only cert-manager, the Traefik config and node sysctls. The operator chart is in `deploy/modules/platform`, used by the local root only.
- The ECR pull secret and its `ecr-refresh` CronJob live in `deploy/modules/login/ecr.tf`, per namespace — not in the `registry` root.
- The spec's "blue/green by `build_id`" is overridden by the same spec (lines 323-326): whole-world cutover.
- `HostEndpoint.cert_hash` is the WebTransport certificate's hash. The QUIC listener mints a different certificate that is published nowhere, so there is nothing a native client could pin today (Task 6 fixes the server side first).
- A server that opens an empty store forges a default world itself, in both roles (`world_file.rs` `ensure_world`). On k8s a pod started before the forge would create the wrong world (Task 4).

## Review Focus

1. **A coordinator pod restart changes its IP.** A host that resolved the name once would redial a dead address for ever, and no cut or takeover would happen again. Expected: the next dial attempt resolves anew. Pinned by Task 1 (`dial_resolves_again_after_a_failed_attempt`).
2. **A host restarted while a succession names its ordinal waits, unready, for minutes.** Expected: no probe kills it, the other host is not held back, and it becomes ready after the settle. Pinned by Task 5 (`livez_is_ok_while_unregistered`) and Task 13 (the twin's kill step).
3. **A world pod starts before the forge.** Expected: it waits and says so; it never forges. Pinned by Task 4 (`an_empty_store_waits_when_told_to`).
4. **A native client is given a host whose certificate does not match.** Expected: the connection is refused before the join JWT is sent. Pinned by Task 7 (`a_wrong_pin_is_refused`, `a_public_name_without_a_pin_uses_web_pki`).
5. **The link identity is on a read-only Secret mount.** Expected: the listener starts with the mounted pair and writes nothing. Pinned by Task 2 (`a_read_only_identity_is_used_as_is`).

### Task 6: One client-facing certificate for QUIC and WebTransport

**Files:**
- Create: `crates/server/src/client_cert.rs`
- Modify: `crates/server/src/lib.rs` (`listen` `:427-445`, the `wt_cert` block `:806-820`, `host_endpoint` `:1403`), `crates/server/src/webtransport.rs` (`CertSource`, `SelfSignedCert`, the 60 s reload move here)

**Interfaces:**
- Produces:
  ```rust
  pub const CLIENT_CERT_ENV: &str = "VOXEL_CLIENT_CERT"; // PEM chain; VOXEL_WT_CERT stays as an alias
  pub const CLIENT_KEY_ENV: &str = "VOXEL_CLIENT_KEY";   // PEM key;   VOXEL_WT_KEY  stays as an alias
  pub struct ClientCert { /* current chain + key behind an ArcSwap or RwLock */ }
  impl ClientCert {
      pub fn from_env(lookup: impl Fn(&str) -> Option<String>) -> Result<Self, String>; // both or neither; neither = self-signed, minted once per process
      pub fn sha256_hex(&self) -> Option<String>;  // Some only when self-signed (leaf DER)
      pub fn rustls_resolver(&self) -> Arc<dyn rustls::server::ResolvesServerCert>; // always the current pair
      pub fn reload_if_changed(&self) -> io::Result<bool>; // files only; called every CERT_POLL (60 s)
  }
  ```
