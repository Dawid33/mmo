# Region Collider Genesis — Performance Design

**Date:** 2026-07-07
**Branch:** `region-collider-perf` (from `develop` @ 8ba8790)
**Status:** Design — approved directions, pending spec review

## Problem

Now that `crates/worldgen` generates real continent terrain, bringing a region
online is dominated by physics-collider construction, not worldgen. One region
takes ~9–23 s to build its colliders (release), blowing the 20 s
`REGION_STARTUP_BUDGET` and forcing two integration tests in
`crates/server/tests/threaded_world.rs`
(`roaming_client_cycles_regions_across_threads`,
`walking_input_crosses_a_boundary_on_real_threads`) to be `#[ignore]`d.

## Profiling (this is what the design is built on)

Measured on one region (0,0), release, via `crates/worldgen/examples/collider_profile.rs`:

| Measurement | Result |
| --- | --- |
| Worldgen | ~0.05 s (not the bottleneck) |
| Materialized sub-chunks | 1088 |
| Solid voxels | 34.2 M (avg **31434 / 32768** per chunk — nearly full) |
| **Fully-solid chunks** | **960 / 1088** |
| **CURRENT** `create_mesh` (voxel + insert + snapshot) | **~9–15 s** |
| Pure parry `Voxels::new` shape build (no snapshot/insert) | ~3.3–4.4 s |
| Bulk build, **no snapshot**, all voxel shapes | ~5.7 s |
| Bulk build, **no snapshot**, all full→cuboid | **~0.46 s** |
| Greedy 3D box-merge every chunk (reference only) | ~0.15 s |

Two independent costs stack:

1. **O(N²) whole-`PhysicsState` clone (dominant, ~4–9 s).**
   `attach_voxels_collider_safe` (`crates/game/src/state.rs:318`) calls
   `self.data.physics.snapshot_raw()`, which does `self.data.clone()` — cloning
   the *entire, growing* `PhysicsState` (every collider + broad/narrow phase)
   into the undo log **once per sub-chunk**. Per-chunk cost climbs from ~5 ms to
   ~23 ms across the build as the clone grows. During region **genesis** this is
   pure waste: there is no prior state to roll back to.

2. **Parry voxel-shape build (~3.3 s floor), concentrated in full chunks.**
   960 of 1088 chunks are fully solid (underground bulk). Each still builds a
   dense 32³ `Voxels` BVH.

## Key insight: full chunk → cuboid is collision-identical

A fully-solid 32³ `Voxels` shape has **no** internal collision features: parry
classifies every interior voxel as `Interior` and culls it, so the shape's
collision surface is exactly its six outer faces = a 32×32×32 cuboid. Therefore
replacing a full chunk's `Voxels` shape with a single `Cuboid` (half-extents 16,
centered at body-local (16,16,16)) is **not** a fidelity change — it produces the
same collision surface, just built ~1000× cheaper. No neighbor/"buried" check is
needed; the rule is purely local (`solid.len() == 32768`).

Partial (surface) chunks keep the parry `Voxels` shape, which correctly handles
the internal-edges problem on the terrain the player actually walks on. Greedy
box-merging of partial chunks was measured (fastest overall) but rejected as the
default: it trades parry's within-chunk internal-edge handling for merged-box
seams exactly on walkable surfaces, and the ~0.3 s it saves is immaterial against
the 20 s budget. It is documented below as a future tick-rate lever only.

## Design

Two changes, both in `crates/game`, both behind a new **genesis** construction
path. Nothing about worldgen output changes.

### 1. Non-logged genesis insertion (removes the O(N²) clone)

Region genesis builds the base state; it is never rolled back below itself, so it
must not touch the undo log. Add a genesis path that inserts terrain
bodies/colliders/ECS via the crate-visible raw accessors (`Undo<T>::raw_mut()`,
already generated by the `#[rollback]` macro at `crates/macros/src/lib.rs:676`),
performing **zero** `snapshot_raw()` clones and logging **zero** undo entries.

- `Region::from_chunks` / `from_columns` (`crates/game/src/region.rs:310`,`:320`)
  route through the new genesis path instead of `create_mesh`.
- A new `Rollback::create_mesh_genesis(coords, chunk)` (name TBD in plan) mirrors
  `create_mesh`'s logic — create entity, store `Chunk` + `RigidBodyHandle`
  components, insert a fixed body, attach the terrain collider — but writes
  through raw field access with no logging.
- The existing `create_mesh` / `attach_voxels_collider_safe` stay **unchanged**
  for runtime, undo-safe terrain edits (e.g. digging/chiseling), which genuinely
  need per-edit inverses.

The serialized `GameData` and its `crc32` hash are unaffected: genesis produces
the identical state whether or not it was snapshotted along the way; only the
wasted clones and never-needed log entries are removed.

### 2. Full chunk → cuboid collider

Inside the collider-attach step (both genesis and, for consistency, runtime), when
the solid mask covers all `ChunkShape::SIZE` (32768) cells, build a single
`ColliderBuilder::cuboid(16,16,16)` translated to body-local (16,16,16) instead of
`ColliderBuilder::voxels(...)`. Otherwise build the `Voxels` shape as today.

- The full-chunk test reuses the solid mask already computed in `create_mesh`
  (`solid.len() == ChunkShape::SIZE`) — no extra scan.
- `Cuboid` is a standard parry shape with existing serde; it round-trips through
  `SerializedRegion` parking/restore identically to `Voxels`.

### Combined result

Projected one-region genesis: **~0.46 s** (from ~9–15 s) — ~20–30× faster, ~40×
under the 20 s budget. Per-tick physics also drops sharply (960 cuboids vs 960
dense voxel BVHs in the broad/narrow phase).

## Determinism / rollback (hard constraint)

- **Shapes are deterministic.** Cuboid and Voxels are built from the vendored
  determinism-locked forks (libm / enhanced-determinism / ordered-float); the
  full-chunk rule is a pure local integer comparison. Client, server, and wasm
  run identical code → identical colliders.
- **Rollback bar unaffected.** `hash(before) == hash(after undo)` governs runtime
  mutation reversibility. Terrain colliders are static base-state geometry created
  at genesis and never mutated per tick, so their hash contribution is constant.
  The genesis path adds nothing to the log to be undone; runtime terrain edits
  keep the existing undo-logged path.
- **Parking/restore stays bit-exact.** `SerializedRegion` serializes the whole
  `PhysicsState`; both Cuboid and Voxels are already serde-round-trippable in the
  forks, so a parked-and-restored region hashes identically to the live one.

## Non-goals / deferred (YAGNI)

- **Greedy 3D box-merge of partial chunks.** Measured fastest (~0.15 s) and the
  best per-tick shape, but reintroduces internal-edge seams on walkable surfaces.
  Documented here as the future lever if tick-rate physics cost (not startup)
  becomes the bottleneck; would additionally require verifying `Compound` serde
  round-trip and a playtest that the kinematic character controller doesn't catch
  on seams.
- **Lazy / on-demand collider construction** (build only near entities). Not
  needed to hit the budget; adds lifecycle + rollback complexity. Revisit only if
  region counts or budgets tighten.
- **Heightfield colliders.** Superseded by full→cuboid + surface Voxels for this
  terrain shape.

## Acceptance

1. One-region genesis builds well under `REGION_STARTUP_BUDGET` (target ≤ ~2 s
   with comfortable margin; measured projection ~0.46 s).
2. `roaming_client_cycles_regions_across_threads` and
   `walking_input_crosses_a_boundary_on_real_threads` are un-`#[ignore]`d and pass.
3. `cargo test -p game` (rollback/hash-restore invariants) stays green — no
   determinism regression.
4. `crates/worldgen/examples/collider_profile.rs` retained as a profiling /
   regression harness, wired to a `just` recipe (justfile-sync rule).
