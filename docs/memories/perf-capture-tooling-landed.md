Steps 2–3 of `docs/superpowers/plans/2026-09-19-client-performance-data-handoff.md` are built (handoff gaps 1–9 closed; status table is in that doc's "Progress" section). Follow-up to [[small-world-knobs-investigation]] and [[client-perf-text-diagnostics]].

- `just perf-capture` → `target/perf-capture/<utc>-<adapter>-<world>/` with `summary.txt` (read first), `manifest.json`, logs, `rss.csv`, `gpu.csv`, `diag.txt`. `PERF_CAPTURE_SECONDS=90` makes it hands-off. Also `just trace-join`, `just perf-summary`, `diag_summary.py --timeline`.
- `crates/game/src/perf.rs`: `perf_event!` → `[perf] event=… t_ms=…`, always-on INFO, bounded volume (never per chunk/LOD key/frame). Events before `perf::init` are buffered — the client logger only exists after Bevy's `LogPlugin` builds, but the game thread starts earlier.
- Non-obvious facts found on the way: the server logs via `simplelog` pinned at INFO, so `RUST_LOG` does nothing there; on the client `RUST_LOG` replaces Bevy's whole filter, hence `PERF_LOG=1` + the dedicated `perf_budget` target for `[client-budget]`.
- GPU busy % needs no root: DRM fdinfo (`/proc/<pid>/fdinfo`) gives per-process engine ns + GPU memory on i915 and amdgpu (verified live on i915). nouveau/NVK exposes no engine time. `intel_gpu_top` is unnecessary.

**Why:** the goal is ranking client/server costs from measurements, not code reading; the original symptom was the client not loading on the Intel iGPU.
